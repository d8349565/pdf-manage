# 开发说明

## 运行与构建

使用 Windows x64 和 64 位 Python，推荐 Python 3.12。

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m app
```

运行 `build.bat` 会检查程序版本与当前提交的 Git 标签、安装固定版本的构建依赖、生成图标、检查 Python 语法、打包程序，并静态检查 EXE 的版本与依赖。它不会运行功能测试，也不会启动程序。首次安装依赖需要联网。

本地验证尚未发布的工作区改动时，使用 `build.bat --preview`。预览构建保留当前程序版本，要求同版本标签位于当前提交历史中，明确标记构建日志为本地预览；不创建提交或标签。默认正式构建仍要求当前提交带同版本标签。预览安装器沿用下方固定输出位置，仅供本机验收。

- 程序目录：`dist/ZhiXuPDF/`，不能只复制 EXE。
- 构建报告：`build/build-report.json`，仅保留本机。
- 安装包：安装 Inno Setup 后运行 `build.bat`（或 `build_setup.bat`），输出 `dist-installer/ZhiXuPDF-Setup.exe`。

**安装器构建规则**：所有本地、CI、验收及预览构建，只允许在仓库根目录的 `dist-installer/` 内直接生成安装器，文件名固定为 `ZhiXuPDF-Setup.exe`。
本仓库位于 `D:\code\pdf-manage` 时，完整路径为 `D:\code\pdf-manage\dist-installer\ZhiXuPDF-Setup.exe`。
禁止在 `build/`、临时目录或其他目录编译安装器后再搬运，禁止修改 `/O` 为其他目录或使用 `/F` 改名。
基础程序目录仍为 `dist/ZhiXuPDF/`，OCR 增强包仍在独立的 `dist-ocr/`；这些产物都不加入 Git。

基础安装器只包含 `dist/ZhiXuPDF/`，不打入 OCR 推理依赖或模型。可选增强包的构建命令见 `docs/OCR.md`；
增强包、模型缓存和构建依赖分别保存在忽略的 `dist-ocr/` 与 `build/`，不能加入 Git。
OCR 增强包独立维护：仅主程序升版不触发重建、改版或更改清单。兼容的已发布 ZIP 直接复用，保持文件字节、版本元数据和 SHA-256；仅当 OCR 执行代码、模型、依赖或接口协议实际变化时才发布新版组件。兼容性依据 `protocol`、平台、固定运行库与完整文件摘要核对，`app_series` 是历史构建信息，不作为主程序系列绑定条件。发布前验证旧包与新主程序组合，文档注明是否确需更新，不能只为匹配主程序版本而重打包。
没有 Inno Setup 编译器时脚本仅完成基础程序，不将上一轮安装包报告为本次产物。

打包时 `packaging/license_bundle.py` 从实际构建依赖中收集许可、版权和第三方声明，加入 Python 许可、项目 MIT 许可、AGPL/GPL/LGPL 全文及实际版本的源码入口，保存到 `_internal/licenses/`。缺少上游许可会中止构建，EXE 与绿色 ZIP 的静态检查也会拒绝缺少许可材料的包。构建不在线下载许可；更新核心依赖时，应同时核对仓库内固定的上游许可和版权说明。

`SOURCES.txt` 标明程序版本、依赖版本和正式版对应源码；Git 工作区有未提交修改或当前提交没有同版标签时，会明确标为本地预览，不能拿正式版源码链接代替预览改动的源码。正式发布仍须保持源码、构建脚本、同版标签与附件一致。本次补齐仅影响新构建，已有发布附件需要随之后的正式版本重新交付。

版本标签推送后，Windows 检查流程分别构建并保存基础安装 EXE、独立 OCR ZIP 和验收报告，不将二进制加入 Git。
可用 `python packaging/verify_exe.py --skip-runtime --installer dist-installer/ZhiXuPDF-Setup.exe` 核对安装器与程序的版本一致。

## 页面工具

顶栏按“文件、编辑、页面、文档、扫描、转换、视图、关于”分类。低频配置在“文件 → 应用设置”；缩放、界面恢复在视图子菜单。整理页“页面大小”复用尺寸动作，工具面板的安全组称“安全与副本”；快捷键、权限控制和安装／绿色版管理分支保持不变。菜单动作及主窗口工具按钮不显示末尾省略号，动态副本文案与右键入口保持一致；耗时进度提示仍可使用省略号。

“扫描 → 扫描件增强”支持去底色保留彩色和黑白打印；后者保留灰度，避免硬阈值把纸纹变成黑块或丢掉浅铅笔字。Pillow 在缩略图上分离中性的纸张区域、拟合边界并给出四角建议，背景复杂或边界不可靠时保留整页。推荐范围需核对，可拖动四角、重新框选、输入坐标或向内裁边。四角变换与照明校正在本机完成，不增加 OCR、NumPy 或 OpenCV 依赖。

增强窗口默认开启“自动拉正”，可取消。根据整页实际文字行与横线拟合方向、平滑调整；没有固定半页分界，也不依据样图路径、裁纸坐标或预设倾角分支。接近水平的观测归零，证据不足或变形突兀时保持原状。预览、PNG、PDF 使用同一参数，增加白边保留边缘笔迹。主要面向横排文档，复杂图表、多列和严重折皱需核对，不提供任意形变的三维还原。

增强窗口按可用屏幕设置大小并支持最大化，默认一张完整效果页，滚轮每次换一页。“放大检查”切换细节滚动；“原图对比”按需显示双栏；“调整纸边”进入四角操作，完成后回到效果。强度与坐标收进“更多调整”，长说明放帮助，字层与原件保护提醒保持可见。底图共享、后台串行处理，效果缓存最多四页；像素滚动按页内相对位置联动，隐藏原图仍可后台准备。代次标记丢弃过期结果，未查看页面保留整页范围。应用前预备所有页后一次入撤销栈，取消、失败或工作区改变时不应用部分结果。处理页为图片，文字层不保留；批注、链接或表单页拒绝处理并提示页码。保留标题、附件、页码标签和书签目标；裁纸页书签改为页首。另存 PDF 或导出当前页 PNG。

四角采用半径 24 逻辑像素的命中范围，先检测角点再判断纸面范围，支持从纸边外侧抓取；悬停、选中与拖动有高亮和手形反馈。移动保留按下位置相对角点的偏移，不把角点吸到鼠标；方向键按画布像素微调，Shift 加速。底图按显示尺寸与设备像素比缓存，最多两张；拖动只刷新变化的边线与角点区域。进入裁纸时取消并暂停效果生成，各次松手仅记录范围，点顶部或底部“完成裁纸”后再统一生成预览；底部按钮此时不直接应用文档。坐标输入关闭逐字符处理，展开坐标同时进入裁纸。

主界面与缩略图区接收 PDF、OFD、PNG、JPEG、WebP、BMP、TIFF。图片复用图片转换的 EXIF 方向、分辨率和多帧读取逻辑，在内存中成为 PDF 页；混合批次保持传入顺序。拖到缩略图区按落点插页，混入图片的批次在阅读区直接追加；从图片创建的未保存文档可继续追加 PDF。原有纯 PDF 阅读区拖放仍打开新标签。“打开”“插入页面”“合并文件”均可选择图片，拖放不是唯一入口。插页批次出错时保持当前文档；图片来源与漂白来源携带另存限制，后台保存进程也会核对，不能通过导出路径覆盖原件。

“编辑 → 粘贴为页面”与 Ctrl+V 接收剪贴板中的本机 PDF／OFD／图片文件及图片位图，截图也能成为新页面。默认插到最后一个所选页之后；按 F8 显示页面栏，点击缩略图区的页面间隙会显示插入线，再粘贴时按该间隙插入。右键菜单提供对应位置的粘贴入口；空文档接收多个文件时合入同一标签，整批只产生一次撤销。插入线使用页面列表及选择快照，选页、切换文档或内容变化后不会复用过期落点；单纯同步选择不清除落点，保留原有框选、多选和拖动操作。

在缩略图区或整理页面选页后，Ctrl+C 或右键“复制页面”建立不可变选择快照，Ctrl+V 复用插页落点。同文件及本窗口其他标签可反复粘贴，保留文字、矢量、批注和复制时的旋转／编辑，并生成独立页标识。来源被复制快照持有，源标签关闭后仍可粘贴；剪贴板中只写随机句柄，PDF 字节及密码留在窗口内。只保留一组快照，关闭窗口后失效，不承诺跨窗口或跨进程传递。正文文字复制仍使用阅读区快捷键，页级复制只在页面视图内生效。来源复制／修改权限均检查。

Ctrl+拖动页面按落点复制，普通拖动继续移动；两种操作使用不同的 Qt 拖放动作，复制复用工作区插页及撤销链路，不读写系统剪贴板。复制时为每个来源／原复制组分配新的 `PageRef.copy_group`；保存时各复制批次使用独立的源文档句柄，避免缓存复用令批注对象联动。表单字段在批次间分开命名，同一批次内合法的跨页关联保留；相关字段与对象签名逐页核对。含表单的逐页导入使用新句柄，重排／抽取通过重建保留 AcroForm，避开引擎复用句柄丢字段及 `Document.select` 移除表单目录的行为。后台保存通过既有序列化传递复制组。

顶部页码区提供“第一页／最后一页”，直接复用 `go_to_page`；按钮状态按当前阅读组的首尾更新，空文档、单页及切换标签后不沿用旧文档页数。

剪贴板仅在用户执行粘贴时读取一次并快照，优先处理文件清单；不根据剪切标记移动或删除原文件，不下载图片网址。文件检查和转换沿用后台导入。位图写入应用自有、带锁的临时工作区，生命周期由 `PdfStore` 管理：页面和撤销记录仍引用它时保留，释放来源或关闭窗口时清理；切换剪贴板不会影响保存。目标只读、源文件失败、取消或导入期间工作区改变时不插入部分结果。文本输入框保留自己的粘贴键；页内图片仍由插入图片功能处理。

页面尺寸从“页面”菜单或整理工具条进入，骑缝章从“文档”进入，纠偏与增强从“扫描”进入。应用前固定工作区与范围，全部准备成功后一次写入撤销栈。取消、失败或工作区变化时不应用部分结果；首次保存另存，读写层拒绝覆盖来源。

`page_geometry` 以不可变页面编辑记录等比变换内容流，保留原始字体、矢量和图片，统一调整可见边界与批注、表单、链接坐标；保存时同步传入页面的跳转目标与大纲位置。旋转和 CropBox 按可见页面语义换算，原裁剪区域继续裁剪。命名定位与文档自动动作暂不支持，来源句柄缓存限制信息，实际后台保存的元信息也会传回主进程，保证保存后继续编辑时一致。

骑缝章以一组可管理的 Stamp 批注存储，完整图片按参与页顺序分片，嵌入原始 PNG/JPEG 供保存重开后调整，支持透明背景。页面位置按可见纸张的边缘计算；原始页面内容和表单不扁平化。改变纸张时印章跟随内容缩放，界面提示核对贴边情况。普通批注浮框不接管骑缝章，整组操作从专用窗口进行。

纠偏仅使用已有 Pillow，在有限分辨率灰度预览上估角，并通过页面内容变换应用 ±10° 内的旋转与等比补白，不重采样 PDF 中的原始扫描图片、不依赖 OCR 运行库。低可靠性建议不自动勾选，支持手动微调；空白页和含批注／印章／表单的页分别跳过。自动分析有进度、可取消；关闭分析窗口会请求取消，分析期间冻结范围与结果控件，防止并发切换范围产生过期结果。

三项工具共用连续滚动预览，进入可见区域时按需准备页面；同一预览最多一个后台渲染任务，图像缓存最多八页。修改印章大小、位置或纠偏角度时复用页面底图更新叠加效果，范围切换通过代次标记丢弃过期结果，关闭窗口取消后续预览。骑缝章默认隐藏已有印章管理、删除及高级位置设置，只保留选图、范围和大小；范围输入框仅在指定页码时显示。

本轮授权验证的命令、72 项新增检查和 318 项定向回归结果见 [验收清单](ACCEPTANCE.md)。

## 打印排版

“排版方式 → 小册子（对折装订）”在所选逻辑页序末尾补齐到 4 的倍数，按纸张生成正反面各两个槽位；空白使用 `None` 保留位置，不向工作区插页。`build_sheets` 与 `face_cells` 同时驱动预览和输出，左右装订交换每面的两个槽位，反序选项按物理纸张反序。默认横向、短边自动双面；显式纵向使用长边自动双面。

“仅正面／仅反面”在发送时过滤纸面并关闭驱动自动双面，预览保留两面并标明本次不打印的纸面，便于核对。手动双面进纸方式与反面是否反序由打印机决定，界面提示先少量试打。普通多页排版参数保留，退出小册子后恢复；颜色、页码范围、纸张、页边距和后台取消沿用原实现。

## 验证

安装器的 `pdfcontext` 选项按当前用户登记 PDF 右键入口。拆分使用 `--split-pdf`；合并由 `--pdf-shell-server` 进程外 COM 接收完整选区，每次调用打开独立窗口。窗口全关后空闲 60 秒退出；升级取消该选项或卸载会清理两项入口及专用 CLSID。

`markdowncontext` 选项为 `.md`、`.markdown` 登记“转换为 PDF”入口，命令为 `--markdown-to-pdf "输入.md"`，直接打开预填文件的 Markdown 转换窗口。升级取消该选项或卸载时清理专用菜单项。Markdown 和 Word 转换窗口支持拖入本机文件；Word 窗口复用现有文件夹扫描、去重及子文件夹选项。修改右键入口后需要重新构建并安装更新的安装包。

源码运行也可用 `python -m app --split-pdf "输入.pdf"` 或 `python -m app --merge-pdf "一.pdf" "二.pdf"` 检查入口预填行为。`tests/test_shell_split.py` 使用合成 PDF 检查入口加载、每 N 页拆分、来源保护和窗口正常退出；页面插入回归见 `tests/test_insert_pages.py`。资源管理器多选与安装卸载需要重新构建安装包实机验收。本轮检查与验收项目见 `docs/ACCEPTANCE.md` 顶部。

```powershell
.venv\Scripts\python.exe -m compileall -q app packaging
.venv\Scripts\python.exe -m pytest
```

打印机、Microsoft Word、安装器和复杂 PDF 还需要在实际环境中核对。静态打包检查通过不代表全部功能已经验收。

### PDF 转 Word 版式导出

转换窗口默认传入 `pdf_mode="layout"`，电子 PDF 与已识别 PDF 复用离线 DOCX 导出器，未识别扫描页继续在临时目录补识别。更多选项中的 `pdf_mode="word"` 保留原来的 Word 重排路径及首次导入确认。

版式模式逐页定位文字和表格，保留可确认的混合字体、字色、粗斜体、标题层级及合并单元格。电子页的非文字图形在内存副本中移除可编辑文字后渲染为带页面底色的背景，避免Word实际PDF导出产生透明灰边；扫描页按本行字形掩膜去字，保留原始色块、边线和紧凑彩色图形。定位表格保留原生行列与合并关系，原稿背景提供边线、底色和图形外观，单元格使用透明底纹和边框。

### 阅读优先启动

普通打开在同一用户、登录会话和安装目录内复用已有阅读窗口，以新标签接收文件；同一路径已打开时激活原标签并保留修改。普通命令行传入多个文件时也分别开标签；显式 `--merge-pdf`、`--split-pdf`、转换和工作进程入口保留各自行为。关闭最后一个阅读窗口后退出，不增加托盘常驻或开机启动。

本机转发使用进程锁和限当前用户访问的命名管道，只发送文件路径。主进程先持锁，阅读窗口构建完成后才创建接收端；发送方收到入队确认才退出，等待最多 5 秒，忙碌时顺序处理。Windows 发送方同时将前台激活权限交给已有进程，恢复窗口时保留最大化状态。

整理工具栏和导出面板按需创建，保留原有偏好。首图保留字体兼容和批注外观，文字命中框及悬停摘要稍后在串行队列准备；滚动后也准备缓存命中的可见邻页。当前页复用一份绘制指令和最多两份按提取参数区分的文字解析结果；文字缓存保留原页面引用，关闭或内容版本变化时释放。

普通阅读打开先完成原始字节快照、密码、基础权限和准确页面几何，并尝试一批至多 256 个对象或约 10ms 的签名检查。简单文件直接准备完成，避免短暂只读提示引起布局变化；复杂文件的剩余检查交给首图后的串行队列。检查中保留阅读及基础权限允许的复制和打印，写出与编辑等待检查结束；用户直接请求编辑时先完成检查再执行，异常仍按原规则只读保护。低层 `PdfStore.load()` 默认继续完整检查，只有阅读入口显式选择延后。

`PAGEARK_STARTUP_LOG` 默认关闭；启用后记录 `first_readable_painted` 以及每份文档的载入、实际绘制、辅助信息和保护检查阶段。`request_id` 是本进程内的数字序号，不记录路径、密码或文档内容。窗口出现、图片准备就绪和实际绘制是不同指标，比较前后版本时必须使用同一指标；独立进程重复启动也不代表清空了系统缓存。

### 阅读性能诊断

阅读预览对部分 Identity 映射的 OpenType CFF 字体做本机兼容处理，使用固定版本的 fonttools 解析字符集并核对字符映射。只有命中特征时才建立内存预览副本，保存和导出仍使用原始来源字节。PyInstaller 显式收集所需的动态字体表读取器，第三方许可随程序放入 licenses/。低倍率阅读在滚动停稳后复用既有区域渲染流程，按当前像素密度更新清晰层。

阅读渲染共用串行优先队列，快速滚动时优先显示缓存或低清预览，停稳约 120ms 后请求清晰图。正文缓存仍为 64MiB；缩略图的原始缓存和显示位图合计按 128MiB 预算淘汰。普通批注悬停使用渲染时准备的摘要，不提取整页文字或分析表格。

诊断默认关闭。需要在本机比较阅读表现时，可仅为本次源码运行设置日志位置：

```powershell
New-Item -ItemType Directory -Path build -Force | Out-Null
$env:PAGEARK_READING_LOG = Join-Path $PWD 'build\reading-performance.jsonl'
.venv\Scripts\python.exe -m app
Remove-Item Env:PAGEARK_READING_LOG
```

日志只追加界面事件间隔、排队与渲染耗时、缓存命中、淘汰数量和位图缓存占用，不记录路径、页码、关键词、密码或文档内容。诊断不会自行打开 PDF 或开展模拟测试；设置该变量后，由用户打开需要核对的文件并操作。

批注与文字框选也复用此日志。`annotation_snapshot` 记录批注快照准备耗时、缓存命中及是否仅取几何摘要；`annotation_preview`、`annotation_cache`、`annotation_apply`、`annotation_refresh` 分别记录候选预览、图片缓存、工作区应用和视图刷新耗时；`text_selection_snapshot` 记录首次框选从请求到文字准备完成的等待时间。缓存命中耗时为实际查找时间；后台排队计入等待时间，不将这些记录当作原反馈文件的修复前后对照。

几何批注冷缓存只在后台准备摘要；文字类工具冷缓存通过既有后台任务准备轻量快照，快照返回后核对页面和工具是否仍相同。文字框选使用阅读串行队列，准备期间记住拖动终点和松开状态，取消、切页或文档变化后丢弃结果；表格排版仍在复制时按需准备。缓存查询不会等待原生渲染锁。

批注摘要和编辑准备使用 `iter_annotations()` 沿原生批注链顺序读取，避开固定版本引擎逐条按 xref 从头查找的重复工作；保留标识去重以及链接、弹出框和表单的原有边界。框选文字先筛选相交的块与行，再执行原来的逐字命中，不据页面是否有图片或线条跳过表格分析。

该方案减少程序自行更新的行为，不能保证消除安全软件误报。SmartScreen 会检查文件及发布者信誉，新文件即使已签名也可能提示；正式分发应使用一致的可信发布者身份签名程序与安装器，保持现有目录式打包、禁用 UPX，不能引导用户关闭杀毒或绕过证书验证。依据见 [Microsoft SmartScreen 信誉说明](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation)。

新增回归代码见 `tests/test_updates.py`，本次仅做源码与打包配置静态检查，未运行模拟测试、联网功能验收、安全软件扫描或安装升级验证。发布前需由用户核对手动检查、自动提示与关闭选项、网络失败后重试、打包后的 HTTPS 能力及保留文件关联的覆盖安装。

## 版本与提交规则

初始版本为 `0.1.0`，初始化提交对应标签 `v0.1.0`，描述为“初始化仓库”。

以后程序版本与 Git 版本保持一致：

1. 每次提交前更新 `app/__init__.py` 的 `__version__`，格式为三段数字。
2. 修复问题或小改动递增第三段，新增完整功能递增第二段。
3. 提交后创建同版本的注释标签，例如程序 `0.1.1` 对应 `v0.1.1`。
4. 同一标签不得移动或覆盖；程序、EXE 文件属性、安装包和 Git 标签使用同一版本。

`packaging/check_version.py` 会阻止版本与当前提交标签不一致的 Git 工作区打包。GitHub 源码 ZIP 没有 Git 元数据时，使用源文件中的版本。

BAT 文件保留 CRLF 行尾；`build_setup.bat` 使用 GBK 编码和 936 码页，Git 属性已声明编码。

Windows 安装与文件关联沿用 `PDFManage` 注册标识，以保持原有打开方式的兼容性。

## OFD 导入

`app/ofd.py` 将常见发票和回单转换为完整的 PDF 工作副本，使用已有 PyMuPDF、Pillow 和系统字体读取能力，不新增依赖。`PdfStore.load` 通过现有 PDF 工作进程执行转换；主进程轮询进度，取消时终止工作进程并清理专属缓存。成功后来源路径仍指向 OFD 原件，`source.data` 保存 PDF 字节快照，供阅读、打印和写出复用。保存入口强制另存 PDF，底层同时拒绝 OFD 后缀和原件文件身份对应的目标。

转换器遵循资源引用、页面实际尺寸、模板和图层顺序、图元边界裁剪及仿射变换。设置归档体积、资源大小、XML 节点、字体数量、图元数量和嵌套深度限制；不执行文档动作，也不读取与显示无关的附件和自定义业务标签。未知可见图元、数字签名、使用权限声明和复杂裁剪等未支持结构会拒绝转换，避免静默输出缺失内容的副本。字体替代、专用字形会单独提示；该路径不验证或迁移数字签名。

`tests/test_ofd.py` 包含生成文档的文字定位回归，以及使用外部授权样本的可选验证。外部样本通过环境变量 `ZHIXU_OFD_SAMPLE` 指定，并将 pytest 的 `--basetemp` 指向仓库外的专用验证目录；未指定样本时仅跳过样本检查。样本检查覆盖打开、像素预览、保存后图像一致性、打印到 PDF、界面取消和另存、原件哈希与覆盖保护。真实样本及所有派生 PDF、图片、运行日志均不得入库；不要将文件名、业务正文或本机路径固化到测试与文档中。当前已用一份授权发票完成上述验证，尚未验证实体打印机和更多银行回单版式。

## 绿色 ZIP 与安装版共用程序

目录式程序构建后，`packaging/make_portable.py` 生成 `dist-portable/ZhiXuPDF-Portable-vX.Y.Z.zip`，现有 `build.bat` 已接入此步骤。安装器脚本与原有右键注册流程保持原样；绿色 ZIP 使用相同 EXE 与依赖，只添加 `portable.ini` 和使用说明，不包含个人 `Data`。

绿色模式将设置保存到 `Data/preferences.ini`，缓存和 OCR 默认位置也在自己的 `Data`；程序内的存储路径保存为可随目录移动的相对路径。绿色版的右键管理入口在“文件 → 右键快捷工具”，每份程序按路径生成独立菜单名和 COM 标识，移除与修复检查登记的路径及版本归属。移动后只清理已经失效且归属于原路径的登记；复制且原位置仍存在时视为另一份绿色版。

发布前除安装版原有检查外，执行 `packaging/verify_portable.py --run-runtime` 校验 ZIP 和解压后的程序。显式 `--native-integration` 会在临时目录启动两个空闲程序，并使用临时 COM 标识验证共存；不创建实际右键菜单，结束后清理测试键与自建进程。该检查需要允许临时注册表写入，普通静态检查不执行此操作。

## 图片右键工具与安装界面

资源管理器图片的“合并为 PDF”通过 `--image-pdf-shell-server` 与进程外 COM DropTarget 一次接收完整选区，支持 JPG、JPEG、PNG、WebP、BMP、TIF、TIFF 混合选择。复用 PDF 多选服务的生命周期，图片任务进入独立的快捷窗口；多图默认自然排序，可拖动或用按钮调整，确认后合并；多帧 TIFF 按帧展开。成功提交结果后请求系统打开 PDF，失败时保留结果及重试、打开文件夹入口；失败或取消不打开结果。`--images-to-pdf` 仍接受显式图片列表，`--compress-image` 保留单图压缩。

安装器固定图片 CLSID 与按程序路径／版本类型生成的菜单方案分别同步维护；图片与 PDF 使用不同 CLSID。已有单图入口修复时移除旧 command，登记与失败回滚、禁用清理共用原有事务。修改登记方案不会自动写入系统，绿色版需在“文件 → 右键快捷工具”修复，安装版需重新构建并安装更新；资源管理器混合多选、Windows 11 菜单及安装卸载仍须实机验收。输出默认在确认顺序后的首张图片旁，先在目标磁盘暂存，再排他提交，防止覆盖处理中出现的同名文件。

`app/imagecompress.py` 只依赖 Pillow 与通用文件提交工具。JPEG 使用质量 85、保留来源色彩采样并优化编码，WebP 使用质量 85；PNG 逐像素核对精确调色板候选并保留透明度、颜色配置和文本，BMP 转为 PNG，TIFF 使用无损 Deflate。保留显示方向、尺寸和适用的颜色／EXIF 信息。输出不小于来源时不生成副本；多帧或动态图片明确拒绝，不静默丢帧；单图限制为 6400 万像素。保存前核对来源是否改变，取消或失败清理本次临时文件，不修改原图。

安装任务保留桌面快捷方式与 `contextmenus` 两项，其中后者是唯一的右键工具开关，统一控制 PDF、图片、Word、Markdown。升级取消该项会删除本程序历史及新增菜单；卸载按所属键清理，不改图片默认打开方式或 Windows UserChoice。Windows 11 的经典右键入口通常位于“显示更多选项”。实际资源管理器与安装／卸载行为需在安装后的 Windows 环境验收。

安装界面使用 Inno Setup 6.6+ 的原生现代样式；本机验证编译器为 6.7.3。`packaging/make_icon.py` 在现有图标生成步骤中同时创建品牌向导插图，构建不下载视觉素材。简体中文语言资源固定在 `packaging/ChineseSimplified.isl`，来源为 Inno Setup 官方源码，保留上游署名及 `packaging/licenses/InnoSetup.txt`；许可与构建资源按公开仓库规则维护。WebP 需要 Qt 的 qwebp 插件及 Pillow 的 `_webp`，已纳入打包检查。

需要核查实际注册项时，可为 ISCC 传入 `/DZhiXuPreprocessOutput=仓库内输出路径` 保存展开后的安装脚本；没有该参数时不产生额外脚本。安装器仍只生成到 `dist-installer/ZhiXuPDF-Setup.exe`。
