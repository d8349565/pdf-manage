# 入库范围

仓库只保存别人运行、构建和维护纸序 PDF 所需的文件。

| 入库 | 留在本机 |
| --- | --- |
| 应用源码、启动入口 | 虚拟环境和下载的依赖 |
| 测试代码 | 真实 PDF、Word、Excel 和其他业务数据 |
| 依赖清单、构建脚本、安装器配置 | EXE、安装包、构建报告和日志 |
| 应用图标、合成材料演示截图、`LICENSE` 与第三方许可说明 | 私人赞赏图片、真实文档截图 |
| README、更新记录、本页与开发说明 | 本机配置、密钥、令牌、编辑器与 AI 工具配置 |
| `.gitignore`、`.gitattributes` | 私人开发记录、旧验收记录、旧提交历史备份 |

`.gitignore` 使用明确允许的文件范围。新增项目资源或说明时，需要同时检查内容并更新允许规则。忽略规则不会自动移除已经跟踪的文件。

赞赏图片位于本机的 `app/assets/donation.png`，不进入 Git 源码仓库。本机打包时如存在该图片，会将它带入程序和安装包，显示微信赞赏区；从公开源码构建且没有该图片时，自动隐藏赞赏区。

## 初始化 GitHub 仓库

发布快照使用单独的根提交，提交描述为“初始化仓库”，标签 `v0.1.0`，不带入旧提交中的私人邮箱和开发记录。旧历史在本机留作备份。

推送时只推送准备好的初始化分支与 `v0.1.0`。不要将旧分支、旧标签或本机历史备份一并公开。

生成的程序和安装包适合放在 GitHub Releases，而不是源码仓库。发布前单独检查待上传的文件。

OCR 增强包单独分发，包含模型、字符字典和推理运行库。源码仓库仅保存接口、固定依赖、模型校验值、构建脚本及许可说明；
不接收 ONNX 权重、下载缓存、增强 ZIP、基础程序目录或安装 EXE。
增强包安装到 `%LOCALAPPDATA%/ZhiXuPDF/ocr/`，基础安装器不会将其复制到程序目录；主程序卸载也不会自动删除这个独立组件目录。

## 每次提交前

检查暂存文件清单和内容，确认没有真实文档、凭证、私人图片或本机路径。新提交的作者邮箱使用公开的 GitHub noreply 邮箱，避免把私人邮箱写入提交记录。
