## 运行

在仓库根目录，沿用项目现有 Python 环境和 `requirements.txt`。当前仓库实际使用 **PyQt6**，不是 PySide；不要同时引入第二套 Qt 绑定。

```bash
python -m pip install -r requirements.txt
python -m app.pdfcompareui old.pdf new.pdf
```

也可启动主程序，从 **文档 → 两份 PDF 对比（实验）** 进入。先选择磁盘上的旧版、新版，再点击“开始比较”。本原型不读取已打开标签页的未保存修改，路径栏明确提示这一点。受保护文档可填写有权限的密码。

左侧列出全部页面组和未配对页，点击切换。顶部显示版本文件名及各自页码。“差异叠加”显示原始颜色背景上的彩色差异，亦可切换两版原页及差异框。下方下拉框定位区域，“上一处／下一处差异”跨页导航；Ctrl+滚轮缩放、拖动画布、适合整页。缩放仅放大本次比较栅格，不产生额外检测精度。

发现页面对应不正确时，点击左侧“调整页面配对”，填写一组或多组已确认对应的旧版／新版页码，再点“重新比较”。两版页码必须按顺序递增，不能重复或交叉；其余页面在指定位置之间重新配对，未配对页面保留。移除所有指定后重比可恢复原配对方式。手工配对只用于本次工具会话；同一来源文件未变化时，调整严格模式等设置重比仍保留指定页对，换文件或来源发生变化后不沿用旧指定。取消或失败保留上次完成的结果。

“更多设置”默认收起，包含配对方式、严格像素比较、整页平移容差和批注范围。结果使用“当前设置下未检出差异”，不等同于内容完全相同。严格模式仅关闭过滤，不提高渲染分辨率；金额、小数点等重要细节仍需核对原文件。切换到原页时保留当前差异定位。

窗口沿用主程序的字体、控件和主题：顶部并排选择两份文件，左侧查看页面配对，右侧核对预览。密码在“更多设置”中填写；文件容量、颜色含义和比较边界可点“使用说明”查看。文件未选齐时不能启动，比较与预览期间冻结对应控件；整页模式随窗口大小调整，手动缩放和区域定位不会被窗口调整重置。单独运行预览窗口也复用主窗口样式。

图例：红为旧版独有的前景像素，青为新版独有的前景像素，橙为其他变化，蓝框为当前定位。这是基于像素与白底距离的分类，不是文字新增、删除的语义解释；一处改字可同时包含三种颜色。

不安装 Qt 时也可仅用现有 PyMuPDF、Pillow 运行比较核心：

```bash
python -m app.pdfcompare old.pdf new.pdf --output comparison-result --preview 1
python -m app.pdfcompare old.pdf new.pdf --output strict-result --strict --pairing index
python -m app.pdfcompare old.pdf new.pdf --output aligned-result --align-pixels 2
```

输出目录必须不存在，拒绝覆盖已有目录。`summary.json` 是开发诊断数据，`--preview 1` 额外保存第一组原图、差异框图和叠加图；没有向主界面增加“导出差异报告”产品功能。`--ask-passwords` 通过交互输入两版密码，不在命令行暴露；`--no-annotations` 排除可见批注。

## 第一阶段的实现选择

| 内容 | 原型行为与边界 |
| --- | --- |
| 页面配对 | 64×64 原色缩略图、文字词袋和首个非空文本行特征，做单调序列动态规划；允许插入／删除。文本只辅助配对，实际差异取决于视觉渲染。没有调用 OCR。 |
| 复合修改 | 只依靠共享正文模板会把“改金额＋改色＋删图”的原页配到新增页，已先复现失败，再增加标题权重修正；合成回归覆盖这一情况。 |
| 配对置信度 | 配对成本大于 0.3 时提示人工核对。相同页、重复模板、共同页眉、重复空白页和大范围重排仍可能歧义，低成本也不等于保证正确。未配对页标“可能新增／删除”，不冒充确定结论。 |
| 配对回退 | 可选择按页号比较，该模式跳过全部指纹生成；单独使用时不解决插页错位。两种模式都支持手工指定有序页对，在指定位置之间分别配对。尚不支持交叉页对／任意重排、章节识别、页码页眉忽略或跨页文字重排处理。 |
| 渲染 | 同一 PyMuPDF 版本、RGB、白底、同一物理缩放，默认包含可见批注。只使用原始 PDF 颜色，不经过阅读配色。不同尺寸置于同一左上角画布，不相互拉伸。 |
| 差异 | Pillow `ImageChops.difference`，取 RGB 最大通道；默认高斯模糊 0.5px、阈值 24/255、保留至少 8 像素的连通域。与现有 `colorcleanup` 使用相同基础库，未把针对清理效果的算法直接套作版本比较。 |
| 区域 | 按连通域过滤小噪点，再扩张聚合附近差异。记录画布像素框、缩放、差异像素数；最多 200 个导航区域，更多区域合并到最后一框。页面大小变化或未配对空白页也有可导航提示。 |
| 严格模式 | 阈值 0、模糊 0、最小连通域 1；可复核当前栅格中被容差过滤的细小修改，同时会放大扫描和抗锯齿误报。仍使用同一有限分辨率，不能恢复渲染时已丢失的细节。 |
| 平移 | 默认关闭。可显式开启最多 2px 的整页平移补偿；核心允许 0–4px。仅在误差改善至少 30% 时采用并记录位移、显示提示，不做旋转、缩放或透视校正。原页保持未补偿内容，定位新版时换算偏移。 |
| 保护 | PyMuPDF 只读打开，认证及复制权限不足时报错；允许只读查看签名文件，不验证签名，也不保存、解密或合并来源。比较前后核对文件状态，预览时再次校验；来源变化要求重比。 |
| 范围 | 默认每份最多 200 页、512 MiB，110 DPI，每组画布最多 200 万像素；核心校验上限分别为 300 页、200 DPI、400 万像素。碎片化差异超过 10 万行程时停止，避免无限增长。 |

## 实际验证

环境：Linux x86_64、Python 3.12.14、PyMuPDF **1.28.2**（与仓库固定版本一致）、Pillow 12.3.0、PyQt6 6.12.0、Qt offscreen。全部使用生成的 PDF，没有读取真实招投标文件。

生成证据及运行定向测试：

```bash
python -m app.pdfcompare_demo --output compare-validation
python -m pytest tests/test_pdfcompare.py tests/test_pdfcompare_ui.py -q
```

输出目录须为新目录；包括 17 组源 PDF、逐组 JSON 和原页／彩色证据图、`measurements.json`。默认参数结果如下，像素数不能跨不同分辨率直接比较。

| 样例 | 默认结果 | 差异像素（默认／严格） |
| --- | --- | --- |
| 完全一致 | 一致 | 0 / 0 |
| 金额 120000 → 125000 | 正确定位到金额行 | 84 / 118 |
| 删除图片／增加图片 | 检出，区域正确 | 各 19,872 / 19,872 |
| 蓝色块改红色 | 检出，原始颜色未被阅读配色抹去 | 20,803 / 20,803 |
| 3 页中插入 1 页 | 旧1→新1，新2未配对，旧2→新3，旧3→新4 | 后续匹配页均 0 |
| 同页改金额、颜色、删图，再插页 | 原页仍配对并检出修改，新插页未配对，后续页一致 | 通过复合样例 |
| 删除中间页／插入空白页 | 明确未配对位置，后续页一致 | 空白插页也有整页定位提示 |
| 空白相同／空白尺寸变化 | 前者一致；后者提示尺寸变化 | 均 0，尺寸变化有独立状态 |
| 增加可见批注 | 检出；排除批注后为一致 | 2,048 / 1,987 |
| 随机通道噪声 ±8 加 120 个暗点 | 默认一致，严格模式大量误报 | 0 / 582,458 |
| 同图 JPEG 质量 85 | 默认一致，严格模式误报 | 0 / 109,218 |
| 同图放大 2 倍后嵌回相同纸面 | **仍有误报，不能视为正文修改** | 100 / 37,121 |
| 噪声叠加真实黑色标记 | 真实新增标记仍检出 | 3,436 / 582,460 |
| 整页横移 1.3 PDF 点 | 默认检出大量位移；开启 2px 补偿后明显降低 | 默认 25,592，补偿后 413；实际采用 (-2,0)px |

17 组中 16 组达到视觉内容变化的预期分类，重采样样例保留已知误报。回归测试对该限制有专门断言，**测试通过不代表 17 组均无误报**。另有真实单像素改动的测试，确认默认过滤会漏掉该变化、严格模式可检测。不要通过继续调大阈值，把招投标中的小数点、细线等重要改动一起过滤。

专项新增测试 **33 项通过**，覆盖以上样例、实际后台进程、进度与取消、权限、文件被替换、原文件 SHA-256 不变、CLI 拒绝覆盖、实际 Qt 导航／缩放／原页切换和启动延迟导入。

包含阅读渲染、配色、菜单、启动、任务调度与 PDF 后台进程的最终回归 **150 项通过、3 项按环境边界排除，73.79 秒**。排除前实际执行过这三项，在未修改的 `cce1043` 独立 worktree 上复现同样失败：

- `test_immediate_progress_is_painted_before_native_work_starts`：offscreen 中首次绘制时序不符合该测试的原生窗口假设。
- `test_local_handoff_acks_before_opening_and_preserves_queued_order`、`test_closing_reader_releases_handoff_while_converter_stays_open`：此环境的 Qt 本机 socket 无法监听。

没有把这些已有失败改成跳过，也没有修改无关模块。实际 Windows 桌面、安装包、真实扫描仪来源、中文招标文件与多显示器仍需实机验收。

## 性能与集成

同一环境，420×594 PDF 点的生成页、默认参数、两版页数相同且仅中间一页改金额。核心独立 Python 进程实测；RSS 包含 PyMuPDF 与 Python 基线，不含主窗口。数字属于样例测量，不能外推为所有扫描件的承诺。

| 每份页数 | 核心耗时 | 进程峰值 RSS |
| --- | --- | --- |
| 1 | 0.265 秒 | 71.8 MiB |
| 20 | 4.436 秒 | 73.9 MiB |
| 200 | 45.787 秒（另一轮 44.200 秒） | 80.6 MiB |

1／20 页在复合配对修正前测量；200 页在最终配对实现重新测量。内存未随页数线性驻留全部栅格图，但扫描大图、特殊 PDF 对象、平移补偿和预览会产生不同峰值。页面配对 O(N×M)，本阶段用页数上限约束，不承诺千页招标文件直接处理。

| 文件 | 接入方式 |
| --- | --- |
| `app/pdfcompare.py` | 无 Qt 的纯比较核心与 CLI；没有导入 `PdfStore`、阅读配色或 UI。 |
| `app/pdfworker.py` | 新增 `compare` 任务及 `compare_pdf_versions` 包装，复用现有 `_worker`、临时工作区、进度事件、取消后结束子进程和清理。每次工作进程独占自己打开的文档，避免多线程共享 PyMuPDF 文档。 |
| `app/pdfcompareui.py` | 复用 `run_operation`，比较仅由点击触发；概览只保存元数据，选中一组再按需预览。会话缓存最多两组，按 Pillow 每像素 4 字节估算不超过 48 MiB，超限先淘汰最早访问的组，不预加载全部页。缓存命中前在线程中校验来源状态；来源变化拒绝旧预览并清缓存。重新比较成功及关闭工具时释放缓存，关闭还清除图像、密码和结果；主菜单关闭后删除对话框。48 MiB 仅为缓存像素预算，不包含 Qt 画布、切页中间图像或工作进程，不是程序总内存上限。 |
| `app/ui.py` | 仅增加文档菜单动作及延迟导入方法，其他阅读路径没有算法、计时器或额外渲染。 |

当前对比工具和任务进度沿用项目模态流程，任务期间界面事件循环保持响应、可以取消；不承诺同时操作主阅读窗口。若后续要求边读边对比，应改成独立非模态工具窗口和专属异步任务队列，继续保留进程隔离及过期结果拒收。

普通阅读额外以同一 20 页样例对照未修改主分支，5 轮交替启动测量空窗口、首张可读页面与 RSS；原始测量随验证附件提供。两边均未导入比较模块。offscreen 的短时计时波动明显，因此不据几十毫秒差异宣布性能改善或证明完全无退化；150 项回归中的缓存、缩放、拖动调度、原色阅读与延迟加载约束均通过。

后续优先事项：真实中文招标书与扫描来源校准、重复页／共同页眉的配对提示、可见范围的高分辨率复核、扫描角度及缩放漂移评估。语义条款解释、AI 总结、报告产品化和修改／合并原件不在本阶段范围。

## 内容对比的样本与资源验收约定（候选 v1）

本节记录内容比较开发前固定的目标与输入，后续原型进展见末节。标准答案不来自比较算法；以下“应当”均是验收要求，不能直接当成已实现能力。

### 固定样本

运行 `python tests/pdfcompare_acceptance_samples.py --output build/pdfcompare-acceptance-v1`，输出目录及同名 ZIP 必须不存在。生成器仅依赖现有 PyMuPDF、Pillow 和标准库，位于 `tests/`，不进入 `collect_submodules("app")` 的应用打包范围。PDF、扫描图及报告留在忽略的 `build/`；不使用业务资料。

每组包括 `old.pdf`、`new.pdf`、`expected.json`，总索引为 `index.html` 与 `manifest.json`。答案含指定变化、未变化的源文本、页码、PDF 点坐标、文件 SHA-256；内部块 ID 只写答案，不出现在 PDF 正文、隐藏文字或批注中。固定随机种子用于扫描噪点。每轮验收锁定同一份文件及校验值，不能为适配算法修改答案；需要新增情况时提升样本版本。

| 编号 | 样本 | 必须核对的结果 |
| --- | --- | --- |
| S01 | 两份内容、版式相同的中文文件 | 不报告内容修改 |
| S02 | 改字号、行距、页边距，2 页重排为 3 页 | 能定位对应段落，不把重排当正文修改 |
| S03 | 全篇重排，同时改金额、0.5%→5%、不得→可以、米→件 | 四处关键变化都检出，不能用容差或归一化抹掉 |
| S04 | 付款条款移动到后面，正文不变 | 对应正确，允许提示移动，不伪报删掉再新增 |
| S05 | 同一条款跨页移动，同时改金额 | 同时定位移动与实质修改 |
| S06 | 一个长段落由 1 页排到 2 页 | 允许一对多位置；反向比较还须验证合并 |
| S07 | 新增培训条款、删除售后条款，后续重新编号 | 新增／删除准确，编号变化可列为结构变化，不使后续正文全部误报 |
| S08 | 两个标段正文几乎相同，只改第二标段金额 | 不能配到第一标段，修改对应的章节须正确 |
| S09 | 两份完全重复且没有独特上下文的条款，一份修改 | 检出差异并表达配对歧义；允许多个旧文候选，禁止伪造唯一确定关系 |
| S10 | 设备表格行重排，改设备乙的数量和单位 | 按设备与列含义对应，不将别的行／列的相同数字当作同一单元格 |
| S11 | 两张图片重排，一张缩放、一张改色 | 区分外观位置变化与图片内容变化；文字比较未覆盖图片时必须明示 |
| S12 | 同一正文重新扫描，分辨率、JPEG 压缩和噪点不同 | 不把噪点直接定性为正文修改；识别不足应列待核对 |
| S13 | 扫描件重排并修改金额 | OCR 结果有原图依据；不能把识别失败当作无差异 |
| S14 | 文字页与扫描页混合，只改扫描页金额 | 正文页不重复 OCR，扫描页不能静默跳过 |
| P020 / P100 / P200 | 20／100／200 页低密度中文文字，每页有共同模板，仅一处金额修改 | 测规模增长；不能外推为密集表格、复杂图片或扫描件的性能 |

生成时只检查样本是否完整、页数是否符合定义、扫描页是否确实无文字层；不把这些检查算成功能验收。完成样本定义后，还应加入密集文字／表格、旋转／裁剪、多栏、加密及异常文件边界，以及未参与开发调参的新组合。真实文件验收另行获得授权，不能用这些简单样本代替真实场景覆盖。

### 如何判定通过

- 在这份固定样本集中，关键金额、小数点、否定词、单位的已知修改必须全部检出；不能用总体百分比掩盖关键漏检。
- S01、S02、S06 的正文误报应为零；明确的排版变化提示单独计数。S04 的移动以内容顺序关系为依据，不把前面插页造成的全部页码偏移都算移动。
- 每条报告必须能定位两版原文或明确的单边新增／删除，不能只有摘要、没有原文证据。段落跨页可对应多处位置。
- 记录漏检、误报、错误配对、需要人工核对的数量及自动覆盖率；不得以“全部标为待核对”冒充成功。S09 是专门的歧义例外。
- 用户纠正、取消、失败、文件变化后重比都应保持正确状态；取消不产生部分成功结果，原文件校验值保持不变。
- 冻结开发集后另做保留验收集，改变金额、位置、标题及组合；不能针对固定样本标题或块 ID 编写分支。

### 体积必须用同条件构建对照

基线分成两层：主分支 `cce1043` 对当前视觉工具 `66938a7`，评估整个功能的增量；当前视觉工具对未来内容对比提交，评估新增内容匹配的增量。两者不能混为同一数字。

在相同 Python、固定构建依赖、资源、压缩与签名条件下分别构建；记录安装 EXE、绿色 ZIP、解压后目录的字节数及增量，并按新增 `.pyc`、DLL、字体、模型定位来源。遵守现有固定安装器输出路径，不覆盖正式发布附件。未做两份同条件构建前，源码大小只能作证据，不能当安装包增量。

当前已确认：`requirements.txt`、`packaging/requirements-build.txt`、`pdf-manage.spec` 在上述两个提交间未变；新增三个应用模块约 57 KiB，计入两个既有模块的接入代码后，Git 对象源码净增 **60,139 字节（58.73 KiB）**。这包含原型的演示模块，不含测试、说明与生成样本，也不等于安装包变化。后续文本比较优先复用现有库；已有离线 OCR 的模型继续独立，不放入基础安装包。引入新模型／运行库前必须重新评估，不能继续沿用“小增量”假设。

候选体积预算：不增加基础运行库和模型；相对明确基线，安装 EXE 增量以 **1 MiB**、解压目录增量以 **3 MiB** 作为首轮目标。它们是待实测的建议门槛，不是已测结果或用户已确认的硬指标。

### 性能分开检查

| 情况 | 对照方法 | 候选门槛／需要报告的指标 |
| --- | --- | --- |
| 没打开对比工具 | 同一生成 PDF、相同窗口／缓存状态，基线与候选交替至少 5 轮 | 启动、首屏、翻页缩放；中位耗时增加同时超过 5% 与 50 ms 时调查；空闲内存增量超过 10 MiB 时调查；不得新增持续任务 |
| 主动比较文字 PDF | 20／100／200 页各至少 3 次独立进程 | 耗时中位数、峰值内存、CPU、临时磁盘；未来内容模式先以 5／20／60 秒为目标，待真实密度样本校准 |
| 比较过程中 | 实际 Windows 窗口，定时测事件循环延迟与取消反馈 | 首次进度不晚于 0.5 秒，交互延迟 P95 目标低于 100 ms，取消目标 2 秒；不能把后台工作进程存在当成界面不卡顿的证明 |
| 含扫描页 | 单独报告扫描页数、像素数、OCR 组件及耗时 | 不套用文字模式预算；只识别需要的页面，未装组件明确提示，不能返回“比较完成”而漏页 |
| 重复预览／关闭 | 往返页面、换文件、打开关闭 10 轮 | 记录缓存命中、主进程与子进程回收、内存是否持续增长；关闭后不得遗留工作进程或任务临时文件 |

内存报告必须区分主窗口、PDF 进程、OCR 进程；总量按同一采样时刻汇总，不能把不同时间的各进程峰值简单相加。现有 48 MiB 只是预览缓存的像素预算，不是软件总内存上限。主动比较必然使用 CPU／内存，目标是有界、可取消、使用完释放；不承诺运行比较时系统资源完全不受影响。

基线工具 `tests/pdfcompare_resource_baseline.py` 仅测现有视觉核心：每档 3 个独立进程，记录内核调用耗时、含启动的进程耗时及 Windows 峰值工作集。它不测主窗口、OCR、安装包或尚未实现的内容算法；报告必须保留这个范围。

## 内容级原型的本机进展 · 2026-10-31

视觉原型把 S02 的纯重排报成 194 个区域，把 S14 中相同的扫描标题和正文也反复列出，不能满足正文核对。为此新增独立的 `app/pdfcontentcompare.py` 内容比较原型并保存在仓库中；尚未接入 Qt 菜单。

它从真实 PDF 提取文字与字符坐标；扫描页按需复用已有独立 OCR 包，记录页码、原图位置与识别质量。匹配使用标题、正文和上下文，表格按行名称及列名对应；纯编号和换行不作为正文修改。结果返回具体的修改前／后片段、上下文和两版位置，条款移动、图片内容变化、歧义、未识别页面分别表达。

固定样本的输入与标准答案保持不变。原型没有接收答案或内部样本块 ID。新结果保存在本机 `build/pdfcompare-content-work/*-content.json`；`acceptance-content.json` 在完成识别后独立核对预设类别和修改文本，不能用区域总数代替正确性。

- S02 与 S06：未报告正文修改；S03：检出金额、比例、否定词、单位四项修改及其位置。
- S04：一条位置调整；S05：金额修改并跨页移动；S07：新增、删除各一条；S08：修改定位在第二标段。
- S09：返回文字差异和多个候选位置，未伪造唯一对应关系。S10：对应设备乙的数量与单位单元格。S11：区分图片内容变化和单纯尺寸／位置调整。
- S12：没有生成正文修改，但低质量 OCR 文字仍标记复核；S13 与 S14：各一项实际金额修改。扫描结果显示有复用缓存，不能拿本次匹配时间充当首次 OCR 耗时。

`tests/test_pdfcontentcompare.py` 的 20 项行为检查通过，包含真实可选 OCR、标题修改（包括独立标题页）、未读取的扫描续页不得判定为确定修改、表格新增行定位、抽取后取消、内存预算前置检查。随后资源守卫收尾和普通阅读延迟导入补查 18 项通过（实际 OCR 已在前一轮执行，未重复运行）。UI 展示的是原型的真实返回值及 PDF 原页，不把样本答案显示成识别输出。

当前原型每份限 200 页、512 MiB；单页最多 4 万字符，两份累计最多 50 万字符，单条款最多 4000 字、最多 4000 个内容单元。字符位置分配前检查文字预算，匹配有取消检查、候选数量与精细差异窗口上限。没有新增运行依赖或 OCR 模型；这些源代码大小不等于安装包增量，安装包和全进程内存仍须在稳定候选上实测。

已验证的主要是这套生成样本及补充边界，不代表任意 PDF 都可靠：复杂多栏、复杂表格、矢量图形与页面装饰、低质量 OCR、标题体系差异很大或大段改写仍有边界。结果应保留原文证据和待核对状态；正式接入应用、真实资料验收及安装包验收尚未完成。
