# 离线文档导出优化方案

## 评估结论

实施前管线能识别文字、写入搜索层、提取有线框表格，但可编辑文档的阅读流还不完整。
本轮已保留 Python、PyMuPDF、标准库 DOCX 和独立 CPU 识别组件，补齐以下流程。
本方案使用本项目的代码、标准文件格式及通用几何设计，参考材料本身不复制入库。

| 问题 | 代码证据与影响 | 设计决策 |
| --- | --- | --- |
| 物理行成为独立段落 | 导出每行创建一个正文段落，编辑后无法自然回流 | 同栏内依据边界、缩进、字体和行距合并正文；标题、列表、表格作为边界 |
| 扫描页转换需多步 | 无文字图片页被导出器拒绝，普通转换入口可能走不适合的路径 | 已安装识别组件时，在任务临时目录补识别后继续；缺组件时引导安装，不联网下载 |
| 双栏横向串读 | 当前先按纵坐标排序并合并同行，会把左右栏拼在一起 | 在合并同行前检测连续竖向留白；分区后按栏内上下、栏间左右组织阅读流 |
| 页眉页脚进入正文 | 页边信息没有跨页角色识别 | 跨页重复、边缘位置及正文间隔联合判定，输出原生页眉页脚；单页标题不作为页眉 |
| 非文字内容缺失 | 提取文字时不保留图像块，整页扫描中的局部图像也不能直接按嵌入图片获取 | 保存独立图片；扫描底图中检测非文字、非表格的图像区域，输出标准嵌入图片和明确警告 |
| 弱边框表格漏检 | 仅确认深色闭合网格，浅色底纹和无竖线表格被当作正文 | 至少表头与两行稳定字段；联合重复列起点、行间隔、数字字段或表头底纹判断，保留推断警告 |
| 短数字误旋转 | 少量近似对称的短字段被独立方向分类误转 180° | 至少三个长区域、80% 高置信方向共识时约束短区域；方向分散时保留原分类，不改写识别文本 |
| Word 空白尾页 | 末尾表格后的默认段落及 CJK 自动行高超过页面 | 依据文字框估计行距，写入细小的空白表后段落，保留源行高和可编辑性 |

## 参考建议的取舍

- 保留问题分类，不直接采用示意代码或固定页面边距。页面尺寸、裁剪、栏宽和字体必须来自当前页。
- 段末标点不能独自证明段落结束；英文句号、缩写和列表需结合几何边界。
- 页边位置不能独自证明页眉页脚；标题、合计和尾部签名应留在正文。
- 嵌入图片清单不能恢复大扫描底图中的局部插图，也不包含全部矢量图形。
- 先验证结构、阅读顺序、可编辑性和内容完整性，再评估外观；不承诺对任意版面逐像素还原。
- 本轮选择可编辑的流式输出。精确浮动文本框模式、复杂透视纠正、全自动字体匹配不作为本轮前置条件。
- 不用金额格式或已知答案替换 OCR 文本，也不以识别置信度单独证明金额正确。

## 执行与验收

1. 先完成剩余网格回归，确认合并单元格与多表格不会损坏现有 TXT/Word/Excel。
2. 建立同栏阅读流和段落聚合，覆盖中英文换行、缩进、列表及表格边界。
3. 在转换入口补按需识别，保留来源、权限、取消、临时目录与目标提交保护。
4. 跨页分离重复页边信息，写入标准页眉、页脚及对应关系。
5. 保留独立插图和可确认的扫描局部图像；不静默删除无法可靠还原的区域。
6. 用不同内容和布局的合成文档验证通用性，再只读用户已授权样本进行实际格式与办公软件互操作验收。
7. 重新构建基础程序并核对依赖隔离；源代码、测试和公开说明只包含通用设计，实际材料留在忽略的验收目录。

## 已执行结果（2026-10-13）

- `documentlayout.py` 统一段落、栏间阅读顺序、表格位置、TXT 与框选复制的结构。
- `raster_grid.py` 恢复闭合线框；`alignment_grid.py` 恢复有证据的弱边框网格和表头底纹宽度。普通正文及不满足证据的对齐块不会静默生成表格。
- `export_input.py` 在 Word 转换任务的临时目录中补识别缺失文字的扫描页；缺组件时支持从转换窗口选择本地增强包安装。
- `word_export.py` 写入原生段落、首行缩进、连续分栏节、栏分隔符、合并单元格、原生页眉页脚和标准嵌入图像；页边缺失时用空白引用防止继承前页内容。
- DOCX 包检查包括 XML 和内部部件关系；逐页文字完整性校验失败时保留全部文字及插图，并报告结构降级。
- `worker.py` 调整短区域的方向判断，检测、识别、字典与 CPU 推理版本保持锁定；基础程序仍没有新增大型依赖。

自动检查覆盖中英文段落、缩进、列表、双栏、表格外正文、多表格、合并单元格、2～5 列、96～216 DPI、旋转和裁剪、浅色底纹、无边框数字字段、多行单元格、图片关系、页边信息、取消和目标保护。
样本文字与实际文档不同，算法没有文件名、业务词语或固定金额分支。

获授权的当前本机 PDF 验证了两张表格（5×5、3×3），TXT 制表符、Word 原生单元格和 Excel 单元格一致，关键金额经原稿核对；原 PDF 哈希不变。
实际 Microsoft Word 16.0 打开生成的 DOCX 并输出一页 PDF，表格、正文和金额保留。
另外三份独立合成文档通过实际办公软件的双栏位置、三页页眉页脚、扫描插图互操作检查。
这些检查不等于 30 页真实办公测试集的 CER 验收，也不保证所有复杂文件的排版准确。

每次 PoC 使用新输出目录。主分支集成后已修复保存提示，并按现行菜单及窗口行为更新旧检查；最终完整回归 451 项通过。
将新增强包从程序中安装后，旧 OCR 文件里的错误文字不会自行变化；应从原扫描 PDF 重新识别或重新转换。

## 输出边界

TXT 保留阅读顺序、自然段和制表符行列，不包含字体或边框。
Word 使用可回流正文、原生表格、页边结构及嵌入图像，保留明确的质量提示。
Excel 只导出确认的表格结构，正文、标题和合计不混进虚构网格。
数字签名效力不迁移，图片形式保留不代表法律或证书有效性。
倾斜或竖排文字、复杂底纹、页边图像与正文交叠、纯文字且无稳定对齐的表格仍需核对。
本轮没有自动纠正严重倾斜、透视或手写识别，也没有启用精确文本框排版模式。

格式依据：[连续分节](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.sectiontype)、
[原生分栏](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.columns)、
[原生表格](https://learn.microsoft.com/en-us/office/open-xml/word/working-with-wordprocessingml-tables)。
