### 研究结论与候选取舍

推荐继续验证的方向是**学习模型提出版面区域，几何与结构约束校验区域内部，再按区域重建 Word**。这不是直接用一个检测模型取代整个转换器，也不是增加某一种票据模板。

| 候选 | 已核实能力 | 本项目中的位置 |
| --- | --- | --- |
| PP-DocLayout / PP-StructureV3 | 支持标题、正文、表格、印章等版面类别；当前 PP-StructureV3 文档提供 `save_to_word()` | 优先评估区域识别与结构解析；Word 导出效果必须独立实测，不能由检测 mAP 推算 |
| RapidLayout | 提供现成 ONNX 推理与多种版面模型；官方也说明暂无单一模型覆盖所有场景 | 隔离实验用适配层，便于与当前 CPU OCR 架构对照；不直接引入正式依赖 |
| pdf2docx | 基于 PDF 几何信息进行 DOCX 重建，Artifex 已停止主动维护 | 作为电子 PDF 的对照基线，不作为扫描件的完整解决方案 |
| Docling | 提供统一文档结构、版面与表格分析；当前官方输出列表没有 DOCX | 可比较结构识别能力，不能把“能读 DOCX”当成“能高保真写 DOCX” |

主要依据：[PP-StructureV3 官方说明](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/pipeline_usage/PP-StructureV3.en.md)、[PP-DocLayout 论文](https://arxiv.org/abs/2503.17213)、[RapidLayout 官方项目](https://github.com/RapidAI/RapidLayout)、[pdf2docx 维护状态](https://github.com/ArtifexSoftware/pdf2docx/discussions/374)、[Docling 官方输出格式](https://docling-project.github.io/docling/usage/supported_formats/)。以上是候选能力和维护状态，不是本项目效果承诺。

### 通用重建算法的边界

1. **输入分流到同一种页面表示。** 电子 PDF 优先读取原有字符、字体、颜色、路径和图片；扫描页使用 OCR 和版面模型。统一保存文字/区域坐标、方向、层叠关系、来源与置信信息，不把 OCR 搜索层中的拉伸字体当成原稿字体。
2. **先找区域，再判断区域内部结构。** 模型的 `table` 标签只是候选区域。必须结合真实线段交点、重复行列对齐、单元格覆盖率、文字归属与跨行跨列关系，区分数据表、外框表单、列表和多栏正文。表单外框可以包含独立字段或子表格，不能自动变成一个大单元格。
3. **分别处理结构与外观。** 结构可靠的表格写原生单元格；表单字段保留坐标；普通正文按段落组织；图片、装饰背景和印章保留图像或原始绘图信息。字体选择和文字宽度应服从区域边界约束，不能通过盲目拉伸凑满整个容器。
4. **使用可解释的保守处理。** 结构或背景分离不可靠时，仅保留对应局部的原貌并提示限制，其他区域照常编辑。报告原生可编辑文字、可编辑表格、图像保留和隐藏 OCR 文字的占比，不能用整页截图冒充高质量可编辑 Word。
5. **用实际渲染检验重建。** 同时看内容、结构、位置和颜色；页数相同、DOCX 能打开、字符计数相同都只是必要检查。错位、串列、换页、文字覆盖、重影和原稿不存在的边框属于独立失败项。

候选模型不能确定数字或正文内容，也不能根据已有样稿答案修正金额。模型置信度不等于最终版式正确率。扫描字体恢复、印章分割和复杂照片上的文字仍需专门验证，不能只凭颜色或形状认定语义。

### 已执行的模型初筛

实验代码：`tests/benchmark_layout_algorithms.py`。依赖和模型只放在 `build/layout-lab/`，没有修改正式依赖清单。使用 RapidLayout 1.2.1、ONNX Runtime CPU，固定置信阈值 0.5、IoU 阈值 0.5、2 个算子内线程；模型文件按发布方登记的 SHA-256 校验。推理阶段禁用网络连接，不使用用户业务文件调参。

初筛为 8 个版式家族、每类 2 个变体，共 16 张生成页面。开发组为有线表、合并表、单栏正文和双栏正文；家族留出组为复杂外框表单、双栏勾选列表、模拟章通知和图示海报。几何基线使用人工生成的准确文字层来隔离 OCR 误差；模型只接收栅格图像。因此耗时与命中数不能当作完整 OCR→Word 的横向性能或质量排名。

初筛观察：两个候选模型均定位到 4 个普通表格区域。PP-DocLayoutV3 定位到 2 个复杂表单的外框，较小的 CDLA 模型把这些区域当作图像；**定位外框不代表恢复了其内部字段**。PP-DocLayoutV3 在这批生成页面上没有检出 2 个模拟印章，不能据此直接替代现有印章处理。两轮区域检测组均值约为 CDLA 每页 0.1～0.2 秒、V3 每页 0.9～2.0 秒，存在负载波动，未计模型加载、OCR 和 Word 重建，不能当作稳定的端到端性能基准。权重分别约 7.4 MB 与 130.5 MB。

初筛报告位于 `build/layout-lab/screening-02/`。普通表格命中、表单外框命中和印章命中分别报告，避免把“检测到了一个框”包装成“还原成功”。这批样例为生成的英文页面，规模小、没有覆盖真实扫描噪声，也没有进行模型驱动的 DOCX 重建，**不是通用算法验收**。它们的结果现已查看，下一轮不能再称为未知测试集。

### 防止过拟合的后续验收规则

- 每轮算法验收必须重新制作未用于调试的新案例，变化内容和结构，不能只替换文件名或几个数字。旧案例保留为回归；新案例一旦被用于定位问题或调参，即转入回归集，修复后下一轮必须再生成新的验收案例。
- 初筛脚本默认使用新的随机种子，并记录种子、生成参数、图像哈希、算法源码快照和模型哈希。`--replay-seed` 只用于明确标记的 `regression_replay`；运行期间源码或模型变化会使验证结果失效。`--generate-only` 仅检查生成流程，不代表算法通过。
- 新种子只能产生模板变体，不能保证消除过拟合。必须持续引入不同结构和独立来源，不能把同一套生成模板的新配色或新字体当成充分的泛化证据。
- 按文档来源和模板拆分开发集、校准集、最终测试集。同一文档的不同页、不同分辨率、电子版/扫描版、改色或旋转版本必须在同一组；不能随机按页分组造成泄漏。
- 覆盖中文和英文、文稿/合同、常规表格、无框表格、嵌套表单、清单、图文混排、红蓝印章、浅底深底、竖排、旋转、低清晰度和多页内容。既有业务失败样本只作私有回归，不入库。
- 在看最终测试结果前固定模型版本、阈值、区域路由和重建参数。测试失败后可以修复通用原因，但该样本转入回归集，泛化声明需使用新的留出来源。
- 内容使用有顺序的字符/词比较，金额和编号逐项匹配；表格检查单元格归属、行列与合并关系；版式按区域检查位置、遮挡、换页和背景颜色。不能只用无序字符计数或被大片白底主导的整页相似度。
- Word 与 WPS 分别实际打开、渲染和做有限编辑检查；记录不支持的环境。检测模型精度、OCR 精度、DOCX 渲染质量和可编辑性分别报告。
- 记录每类失败率、严重错误数、可编辑覆盖率、耗时、峰值内存与组件体积。候选模型未通过这些检查前，不接入正式默认路径、不发布新的“高还原”结论。

候选模型状态：完成资料核实与区域模型初筛；模型驱动的 Word 重建尚未完成验收。现有转换路径的后续通用规则修复与实际 Word 测试见本文最上方记录，不以单份文件改善作为模型选型依据。

## 评估结论

实施前管线能识别文字、写入搜索层、提取有线框表格，但可编辑文档的阅读流还不完整。
本轮已保留 Python、PyMuPDF、标准库 DOCX 和独立 CPU 识别组件，补齐以下流程。
本方案使用本项目的代码、标准文件格式及通用几何设计，参考材料本身不复制入库。

| 问题 | 代码证据与影响 | 设计决策 |
| --- | --- | --- |
| 物理行成为独立段落 | 导出每行创建一个正文段落，编辑后无法自然回流 | 同栏内依据边界、缩进、字体和行距合并正文；标题、列表、表格作为边界 |
| 扫描页转换需多步 | 无文字图片页被导出器拒绝，普通转换入口可能走不适合的路径 | 已安装识别组件时，在任务临时目录补识别后继续；缺组件时引导安装，不联网下载 |
| 双栏横向串读 | 当前先按纵坐标排序并合并同行，会把左右栏拼在一起 | 在合并同行前检测连续竖向留白；分区后按栏内上下、栏间左右组织阅读流 |
| 页眉页脚进入正文 | 页边信息没有跨页角色识别 | 跨页重复、边缘位置及正文间隔联合判定，输出原生页眉页脚；单页标题不作为页眉 |
| 非文字内容缺失 | 提取文字时不保留图像块，整页扫描中的局部图像也不能直接按嵌入图片获取 | 保存独立图片；扫描底图中检测非文字、非表格的图像区域，输出标准嵌入图片和明确警告 |
| 弱边框表格漏检 | 仅确认深色闭合网格，浅色底纹和无竖线表格被当作正文 | 至少表头与两行稳定字段；联合重复列起点、行间隔、数字字段或表头底纹判断，保留推断警告 |
| 短数字误旋转 | 少量近似对称的短字段被独立方向分类误转 180° | 至少三个长区域、80% 高置信方向共识时约束短区域；方向分散时保留原分类，不改写识别文本 |
| Word 空白尾页 | 末尾表格后的默认段落及 CJK 自动行高超过页面 | 依据文字框估计行距，写入细小的空白表后段落，保留源行高和可编辑性 |

## 参考建议的取舍

- 保留问题分类，不直接采用示意代码或固定页面边距。页面尺寸、裁剪、栏宽和字体必须来自当前页。
- 段末标点不能独自证明段落结束；英文句号、缩写和列表需结合几何边界。
- 页边位置不能独自证明页眉页脚；标题、合计和尾部签名应留在正文。
- 嵌入图片清单不能恢复大扫描底图中的局部插图，也不包含全部矢量图形。
- 先验证结构、阅读顺序、可编辑性和内容完整性，再评估外观；不承诺对任意版面逐像素还原。
- 本轮选择可编辑的流式输出。精确浮动文本框模式、复杂透视纠正、全自动字体匹配不作为本轮前置条件。
- 不用金额格式或已知答案替换 OCR 文本，也不以识别置信度单独证明金额正确。

1. 先完成剩余网格回归，确认合并单元格与多表格不会损坏现有 TXT/Word/Excel。

## 输出边界

TXT 保留阅读顺序、自然段和制表符行列，不包含字体或边框。
Word 使用可回流正文、原生表格、页边结构及嵌入图像，保留明确的质量提示。
Excel 只导出确认的表格结构，正文、标题和合计不混进虚构网格。
数字签名效力不迁移，图片形式保留不代表法律或证书有效性。
倾斜或竖排文字、复杂底纹、页边图像与正文交叠、纯文字且无稳定对齐的表格仍需核对。
本轮没有自动纠正严重倾斜、透视或手写识别，也没有启用精确文本框排版模式。
