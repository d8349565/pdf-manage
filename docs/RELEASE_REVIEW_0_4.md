# v0.4.0 集成审阅

审阅范围：v0.3.6 至 v0.3.7 的七个改动文件，以及离线 OCR 功能与新版转换窗口的衔接。
重点是方向选择、文件收集、输出位置、来源保护、取消、安装器与增强包分发。

## 已确认并修复

| 级别 | 触发与用户影响 | 修复与证据 |
| --- | --- | --- |
| P1 | 新版转换窗口在扫描件/OCR 文档导出前强制要求 Word，与独立 OCR 导出路径冲突 | 仅 Word 转 PDF 直接要求 Word；PDF 先检查文字层，仅原生导入路径检查首次确认。真实生成 DOCX 的无 Word 测试通过 |
| P2 | 进度弹窗延迟显示时，用户可修改转换方向、清单或目标，导致操作与反馈不一致 | 活动任务期间阻止清单、方向与路径的变更；任务状态回归核验来源、目标、方向不变 |
| P2 | 文件成功保存后，打开目录失败替换了包含输出路径的成功提示 | 保留成功消息并附加目录失败提示，保存结果和文件路径持续可见 |
| P2 | 本次缺少安装器编译器时，构建结束信息仍会列出上轮安装 EXE，容易拿错版本 | 仅在本轮编译成功后报告安装器路径；基础程序和增强 ZIP 独立构建 |
| P2 | 安装器只设置应用版本，EXE 文件的二进制版本仍为 0.0.0.0，无法对应发布标签 | 增加文件与产品版本资源；实际编译后检查 PE 固定版本和文本版本 |
| P1 | 增强包解包后，Windows 暂时占用目录导致提交失败；实际安装重复复现 | 目录提交及备份恢复增加最多五秒、可取消的重试；真实包在等待约 1.5 秒后安装成功，取消恢复旧组件的检查覆盖 |

保留统一目录与逐份手动路径互不覆盖、文件夹扫描、拖放、Delete 移除、状态颜色及路径省略。
旧测试中要求合并按钮仍在工具栏、打开 PDF 自动最大化、隐藏控件立即收到尺寸事件的断言，与当前公开交互不符；已按实际菜单、窗口尺寸保留和可见控件更新。

## 分发约束

- `ZhiXuPDF-Setup.exe` 安装基础程序目录，不包含 OCR 模型、OpenCV、ORT 或 NumPy。
- `ZhiXuPDF-OCR-win-x64.zip` 是独立增强包，安装到用户应用数据目录，校验主程序系列和全部文件。
- 两种二进制、真实样本、缓存和验收产物不加入 Git。仅源码、固定依赖与通用自动测试入库。

## 验证边界

程序版本、Git 标签、基础 EXE 和安装器版本必须一致；模型增强包的 `app_series` 必须为 `0.4`。
合成检查和单份授权样本不能代替 30 页真实办公测试集的 CER 验收。
Windows 10、普通六核/8 GB 目标机器、实际打印机及安装/卸载仍按产品验收清单核对。

当前完整自动回归为 451 项通过。版本标签触发 Windows 流程，分别保存基础安装器和 OCR 增强包；实际发行检查结果记录在构建报告中。

安装器版本属性依据 [Inno Setup 文件版本说明](https://jrsoftware.org/ishelp/topic_setup_versioninfoversion.htm)显式设置，不以安装界面中的应用版本代替 EXE 文件属性。
