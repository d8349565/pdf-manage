# 多语言维护

应用默认跟随系统显示语言，支持 `zh-CN`、`en`、`zh-TW`、`ja`、`ko`、`de`、`fr`、`es`。中文优先按 `Hans`（简体）或 `Hant`（繁体）字形选择，未指定字形时台湾、香港、澳门匹配繁体，其余中文匹配简体；其他语言先尝试系统的后续显示语言，均不支持时使用英语。

从“文件 → 应用设置 → 界面语言 / Language”选择，下次启动时生效。偏好项为 `interface/language`，默认值 `auto`；沿用安装版的用户配置或绿色版的 `Data/preferences.ini`。更换语言不关闭当前文档。界面语言与 OCR 识别能力分开，文字识别范围仍见 [OCR 说明](OCR.md)。安装器、已有资源管理器菜单、发布说明正文和操作指南截图仍保留原有语言。

## 修改界面文本

`app/i18n.py` 在主窗口及独立图片、Word、Markdown 工具打开前选择语言。中文源文本是查找键，`app/locales/<语言>.json` 的值是译文。缺少译文时先回退英语，再回退中文；损坏的语言文件不阻止启动。部分旧工具的动态错误、后台组件返回的信息尚未迁移，仍可能显示中文。

固定文字使用 `tr('保存')`，包含动态内容时先翻译模板，再代入值：

```python
from app.i18n import tr

label.setText(tr('已选 {p0} 页', p0=count))
```

不要把已经格式化的字符串传给 `tr()`，也不要按中文语序拼接几个已翻译的片段。姓名、路径、PDF 正文、用户书签、批注内容不传入 `tr()`；将这些值作为占位符参数原样插入。`{p0}`、`{p1}` 等占位符必须在所有语言中保留，可根据目标语言调整顺序。

需要保留原始值的元数据使用 `mark_text('OCR 组件')` 标记，在显示处调用 `tr(title)`。快捷键命令 ID、选择器类型、属性名、设置键及中文源菜单目录保持稳定，在匹配或显示时翻译。不要翻译正则表达式、持久化的标识或业务判断使用的状态码。

主题名称及描述、快捷键目录的标签、分类、菜单路径和控件选择器会自动纳入提取。菜单省略号由 `tr()` 统一处理，使菜单显示和快捷键目录使用同一译文。Qt 的确定、取消等标准按钮使用随程序打包的 `qtbase_*.qm`。

## 同步与检查

在已有开发环境的仓库根目录执行：

```powershell
.venv\Scripts\python.exe packaging/sync_translations.py
```

此命令更新 `app/locales/source.json` 的源文本和代码位置，保留现有译文；缺项按语言输出到忽略入库的 `build/translations/<语言>.missing.json`。把待翻译项补入对应语言文件，不用重新翻译整个界面。源文本修改会表现为一个新增项和一个未使用的旧项，可据此调整旧译文；确认无其他入口使用后再删除旧项。

完成后执行：

```powershell
.venv\Scripts\python.exe packaging/sync_translations.py --check --require-complete
```

严格检查源索引、未标记的中文界面文本、缺失译文、空译文和占位符，发现问题返回非零状态。普通 `--check` 允许缺失项，便于分阶段翻译，但仍报告数量并检查占位符。新增语言时更新 `LANGUAGES`、语言 JSON，以及 `pdf-manage.spec` 中的应用和 Qt 语言资源清单。

语言匹配、回退、设置、快捷键绑定的定向检查位于 `tests/test_i18n.py` 和 `tests/test_i18n_shortcuts.py`。使用隔离偏好，不读取真实业务文档。正式构建的静态包检查会核对语言文件是否随包交付；安装版和绿色版共用同一套资源。
